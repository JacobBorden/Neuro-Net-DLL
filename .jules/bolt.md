
## 2026-10-29 - Matrix multiplication loop order optimization in NeuroNetLayer
**Learning:** In `src/neural_network/neuronet.cpp`, the matrix multiplication within `NeuroNetLayer::CalculateOutput()` suffers from severe CPU cache misses when using the standard `(i, j, k)` loop order due to column-major memory access of `WeightMatrix[k][j]`. Reordering the loops to `(i, k, j)` resolves this by allowing contiguous, row-major access to both `OutputMatrix[i][j]` and `WeightMatrix[k][j]`, which yields substantial performance gains and auto-vectorization benefits. However, when using OpenMP parallelization, explicit parallelization across `i` combined with `collapse(2)` on nested loops with data dependencies (accumulation) causes compilation errors or incorrect results. Furthermore, explicit matrix initialization with `BiasMatrix` must occur in an outer loop separate from the main accumulation loop to maintain precision and pass tests. Finally, the zero init and bias add steps can be elegantly combined into a single initialization step (`this->OutputMatrix[i][j] = this->BiasMatrix[0][j];`) prior to the accumulation loop for further small optimization and clean code.
**Action:** Always prefer `(i, k, j)` loop order for matrix multiplications. Use `#pragma omp parallel for` on the outermost independent loop. For equations like $Y = XW + B$, initialize $Y$ with $B$ in the outermost initialization loop prior to accumulation, which improves precision and saves redundant iteration.
