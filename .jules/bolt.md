## 2024-05-18 - Transformer FFN Bias/Activation In-Place Fusion
**Learning:** In the Transformer Feed-Forward Network, the operations `input * W1`, followed by adding bias `b1` and computing `GELU` separately lead to multiple intermediate temporary matrices (`hidden_biased`, `hidden_activated`) which take a toll on execution time due to memory allocation and loops. Fusing the GELU operation directly inside the bias addition using `#pragma omp parallel for` optimizes out these temporaries entirely. A similar optimization can be done for the second layer `+ b2`. The inner GELU logic was implemented directly instead of calling `MathUtils::gelu` which creates a new matrix.
**Action:** When working on deep learning models, always look for opportunities to fuse element-wise operations (bias, activations) in-place instead of creating temporary large output blocks for each step.
